# INT8 paged attention：visible_k 加载掩码对比

仅将 `valid_k = logical_k < kv_len` 改为 `valid_k = logical_k < visible_k`，逐行因果掩码保持原样。修改前后完整源码分别保存为 `before.py`、`after.py`；脚本在运行前断言两份源码仅有这一个差异，且 after 与当前项目源码相同。

本次测量中，prefill 的耗时中位数下降 0.07%～2.40%（不含 visible_k 始终等于 kv_len 的 Q=16 对照）。decode 的差异在 -0.022%～+0.031%，视为没有收益。幅度依长度、batch 和 scale 数量而变。

## 正确性

- 现有 `tests/test_quantized_attention.py` 测试通过，覆盖 head_dim 80/128、decode、带缓存前缀的 prefill、跨 KV 页及零长度 decode。
- 下表 24 组输入均通过修改前后严格逐元素一致检查（rtol=atol=0）。
- 每组均与恢复 BF16 KV 后的 FlashAttention 因果 attention 对照，通过 rtol=0.02、atol=0.005 检查；最大绝对误差为 0.003906。双 scale 的前后半 head 使用不同值。

## 环境和测量

- GPU 0：NVIDIA GeForce RTX 3090 Ti；测试前 GPU 利用率 0%，已占用 175 MiB。
- PyTorch 2.5.1+cu121；Triton 3.1.0；CUDA 12.1；seed=31。
- Q 为 BF16，K/V 为 INT8，scale 为 FP32；query_heads=16，kv_heads=8，head_dim=128；KV block_size=256；BM=16，BN=64，BD=128，num_warps=4。
- 15 轮；每个 CUDA Graph 包含 8 次 kernel，每轮重放 10 次；CUDA Event 计时后除以 kernel 调用数。预热后交替测两版，首轮顺序随机。

- 数据是单层 attention kernel 测量，不能直接换算为整个模型的吞吐率提升。运行期间未锁定 GPU 时钟。

## 结果解释

新掩码仅减少每个 Q tile 最后一个 K tile 中所有有效 Q 行都不可见的 KV/scale/页表加载。BN=64、BM=16 时仍以完整矩阵 tile 执行 QK/PV，循环次数和 tl.dot 的尺寸不变，因此节省有限。decode 中 visible_k=kv_len，加载掩码语义相同。
